# 範本動態照片區塊

每份範本可定義一個照片頁區塊，依上傳的照片數量重複頁面。範例是自行產生的 [Mock 範本](../public/templates/scene-photos-template.docx)，不讀取任何外部參考範本。

## Word 標記

起訖標記各自獨占本文的一個段落，不放在表格、頁首或頁尾：

```text
{{#照片頁}}
Mock 現場照片（標題段落）
表格：一般表頭＋N 個照片格
{{/照片頁}}
```

表格中的每個照片格包住完整、連續的列；起始標記在第一列第一段開頭，結尾在最後一列最後一段結尾。同一頁的所有格須在同一張表格，不能巢狀、重疊或共用同一列。範例每格四列：

| 列       | 寫法                                                |
| -------- | --------------------------------------------------- |
| 編號     | `{{#照片格}}編號{{照片編號}}`                       |
| 圖片     | `{{照片}}`，獨占儲存格的一個段落                    |
| 攝影資料 | 標題與 `{{攝影時間}}`、`{{攝影地點}}`、`{{攝影人}}` |
| 說明     | 說明標題與 `{{照片說明}}{{/照片格}}`                |

照片儲存格須明確設定 dxa 寬度、列高。引擎依寬高扣除儲存格邊界與行高餘量，等比例放入 `wp:inline`，不裁切。原範本的段落、字型、字級、表格框線保留。照片編號會填入全形括號，例如「（1）」，不要在標記外再加括號。

有 N 個格就是每頁 N 張；範本頁面本身應能容納這些格。區塊內不要另外插入分頁、分節；產出時以標題段落的 `pageBreakBefore` 分隔重複頁。`{{年}}`、`{{月}}`、`{{警局}}`、`{{分局}}`、`{{案次編號}}`、`{{案由}}` 等一般欄位照常填入，每頁一致。

上傳及替換時都驗證語法，錯誤會顯示第幾個標記、第幾段及段落片段。含區塊的範本，其照片特殊標記不會列入一般欄位。沒有照片區塊的舊範本保留既有行為，包含原本名為「攝影人」的一般文字欄位。

## 填寫與資料生命週期

只有含照片區塊的文件顯示照片表單。多選或拖放 PNG/JPEG；共用攝影日期預設為台北今天的民國日期，可填共用地點及攝影人。每張照片有說明，可啟用「覆寫共用值」，只修改需要覆寫的欄位，未改的值仍跟隨共用值。支援拖曳排序、鍵盤操作的上移／下移按鈕及刪除；排序後重新編號。

照片狀態以範本 id 為鍵，步驟區、可同步作業區、全部文件總覽共用同一份狀態；其他範本不會取得該照片。單份與 ZIP 下載共用同一個產出入口。照片新增、解碼期間暫停產出。

照片只存在畫面記憶體，不送到後端、不寫草稿、localStorage 或 IndexedDB，也不記錄照片內容。離開流程、登出或重新整理即清除。縮圖直接繪製在 canvas，不建立 blob URL；解碼 bitmap 與畫布會釋放。沒有新增後端照片 API，CSP 與 DOCX 安全限制均未調整。

最後一頁不足時保留空格的框線與標題，內容清空。0 張時顯示產出前提示，輸出移除整段照片頁及其標記段落，不加分頁。

## 限制與驗證

- 每份範本最多 30 張，每張原檔最多 10 MB；檢查 MIME、PNG/JPEG 魔數，解碼前限制為 4,000 萬像素。
- 本機重編碼為原圖格式，長邊最多 1600 像素；JPEG 品質 0.85，會移除原照片附帶的 metadata。
- 只支援本文內一個照片頁區塊、同一張非巢狀表格；每格恰有一個圖片標記，照片欄位須在格內。照片頁與照片格的結構標記請照上述精確寫法輸入。
- 產出檔仍受既有 `docxZipLimits` 限制。容量不足時應減少照片數量／尺寸，不會放寬檢查。
- 超長說明、一般欄位文字及不適合單頁的範本可能使 Word 自動增高列；維護者應在 Word 確認版面。不同電腦的字型與 Word 排版仍會影響實際頁面。

重建 Mock 範本：

```sh
node --experimental-strip-types scripts/build-photo-template.ts
```

產生含寬圖、直圖、XML 特殊字元及第 3 張攝影人覆寫的 2／5／7 張證據：

```sh
node --experimental-strip-types scripts/photo-block-evidence.ts
# 若指定目的地不可寫，可傳入另一個路徑：
node --experimental-strip-types scripts/photo-block-evidence.ts /workspace/ai-use/evidence/photo-block
```

腳本預設目錄是 `/workspace/evidence/photo-block`，每份 DOCX 都會執行既有 ZIP／XML 安全驗證。本次受環境唯讀掛載限制，實際證據位於 repo 未追蹤的 `evidence/photo-block/`，不提交。瀏覽器啟動／監聽連接埠遭環境 EPERM 拒絕，LibreOffice 轉檔也未完成；因此只有 OOXML 結構、Vue DOM 整合與真實 server 上傳驗證，沒有實際 Word／PDF 頁數或瀏覽器截圖宣稱。
