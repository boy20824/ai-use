# 安全基線

這份清單對應目前的服務與畫面。正式密鑰只放在環境變數，`.env.example` 只有示範預設值。

| 控制                   | 作法                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 如何測試                                                                       |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Helmet 與嚴格 CSP      | `@fastify/helmet`，`default-src 'none'`、`script-src 'self'`，沒有 `unsafe-inline`                                                                                                                                                                                                                                                                                                                                                                                | `server/src/security.test.ts` 檢查 `content-security-policy`                   |
| CORS 允許清單          | `CORS_ORIGINS`（或單一的 `CORS_ORIGIN`），不反射未列入的來源                                                                                                                                                                                                                                                                                                                                                                                                      | 同一測試對 `https://evil.example` 確認沒有對應的 `access-control-allow-origin` |
| CSRF                   | `SameSite=Strict` session cookie，再加上雙重提交的 `csrf` cookie 與 `x-csrf-token`；變更請求若帶了來源，必須在允許清單內                                                                                                                                                                                                                                                                                                                                          | 跨站 `Origin` 與缺少權杖的上傳都應得到 403                                     |
| 登入速率與鎖定         | 同一 IP 每分鐘有次數上限；同一帳號連續失敗達到門檻後鎖定                                                                                                                                                                                                                                                                                                                                                                                                          | 失敗兩次後正確密碼仍是 429；另測每分鐘上限                                     |
| 階段到期與輪替         | 登入會刪除該使用者舊階段並發出新 cookie；過期階段會被拒絕                                                                                                                                                                                                                                                                                                                                                                                                         | 第二次登入後，第一個 cookie 不能再讀 `/api/auth/me`                            |
| 正式環境 Secure cookie | `NODE_ENV=production` 或 `COOKIE_SECURE=true` 時加上 `Secure`                                                                                                                                                                                                                                                                                                                                                                                                     | `cookieSecureFromEnv` 與 `cookie.secure`                                       |
| 正式環境階段密鑰       | `SESSION_SECRET` 至少 32 字元，拒絕示範值，並用來簽署 session cookie。示範帳號只在 `SEED_DEMO_USERS=true` 時補上缺少的使用者，那時種子密碼也不能是 `.env.example` 的示範值。正式環境預設關閉，因此不需要 `SEED_USER_*`。啟動不會刪除已存在的使用者                                                                                                                                                                                                                | `server/src/deploy.test.ts`                                                    |
| 同源部署               | 正式環境由同一個來源提供畫面與 `/api`。變更請求的 `Origin` 若等於這個請求的 Host，視為允許                                                                                                                                                                                                                                                                                                                                                                        | 同一測試對 `https://ai-use.fly.dev` 登入，並拒絕 `https://evil.example`        |
| 每個路由的輸入結構     | Zod：登入本文、類別名稱／代號／簡述／步驟、範本連結編號、類別查詢、範本編號、上傳的步驟編號                                                                                                                                                                                                                                                                                                                                                                       | SQL 字串與不合法編號得到 400，回應沒有 `stack`                                 |
| 一致的錯誤回應         | `{ error, message }`，錯誤處理不把堆疊送出                                                                                                                                                                                                                                                                                                                                                                                                                        | 鎖定與驗證失敗的 JSON 不含 `stack` 或 `SQLITE`                                 |
| 稽核紀錄               | `audit_log` 記錄範本上傳／刪除，以及類別的 `category_create`、`category_update`、`category_delete`。成功列的 `result` 是 `allowed`。權限被拒時回 403，並寫入 `result=denied`（操作者、嘗試的動作、目標編號）。不記案件欄位、步驟正文或檔案內容。不記產生文件                                                                                                                                                                                                      | 拒絕列的 detail 與 file_name 是空的；稽核不含 `CASE-SECRET-VALUE` 或填寫值     |
| 檔名與路徑             | 只留檔名，去掉 `..`、斜線、控制字元；不把檔名當路徑。範本檔寫入 `UPLOAD_DIR`                                                                                                                                                                                                                                                                                                                                                                                      | `../../etc/passwd.docx` 存成 `passwd.docx`                                     |
| docx zip bomb          | 限制 ZIP 項目數與未壓縮總大小，並拒絕 ZIP 內的 `..` 路徑                                                                                                                                                                                                                                                                                                                                                                                                          | 超過項目數的 docx 得到 400                                                     |
| 依賴稽核               | `pnpm audit`                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 見下方結果；能修的已升版                                                       |
| 畫面不使用 v-html      | ESLint `vue/no-v-html`，範本名稱先去掉標記字元再以文字節點輸出                                                                                                                                                                                                                                                                                                                                                                                                    | `src/utils/fileName.test.ts`；`pnpm lint`                                      |
| 角色                   | 兩種角色：`sysadmin`、`user`。產生文件：已登入即可。建立／編輯類別與步驟、上傳範本、把範本連結到步驟：系統管理員，或 `can_manage_categories` 的使用者。刪除範本、刪除類別、會員管理：只有系統管理員。留言板：每人可改刪自己的；刪除別人的、改狀態、寫管理員回覆：只有系統管理員。拒絕時回 403 並寫 `audit_log`（`result=denied`）。停用帳號會刪除其全部階段，每個已登入請求都會再查啟用狀態。不能停用自己或取消自己的系統管理員，且至少保留一位啟用中的系統管理員 | `server/src/permissions.test.ts`、`server/src/v12.test.ts`                     |
| 註冊                   | `POST /api/auth/register` 只接受名稱、暱稱、帳號、密碼、確認密碼。帳號不分大小寫且唯一。密碼至少 8 字並以 bcrypt 儲存。本文裡的 `role`、`can_manage_categories` 會被拒絕，新帳號固定為啟用的一般使用者。同一 IP 與全站都有次數上限。錯誤訊息不說明帳號是否已存在。變更請求要過 Origin 與 CSRF                                                                                                                                                                     | `server/src/v12.test.ts` 的權限竄改、洪水、跨站與缺少權杖                      |
| 會員與留言             | 會員名單與變更只有系統管理員。一般使用者改別人的會員或留言是 403，不會套用本文裡的角色或維護旗標。留言作者以使用者 id 判斷，暱稱由帳號帶出。內容最長 2000 字，以 JSON 純文字往返，畫面不使用 `v-html`                                                                                                                                                                                                                                                             | 同檔的 IDOR、停用後舊階段 401、儲存型 XSS 字串                                 |
| 類別與範本生命週期     | 刪除類別只刪除步驟與 `step_templates`。刪除範本才刪檔，並由外鍵一併移除步驟連結                                                                                                                                                                                                                                                                                                                                                                                   | 刪除類別後範本仍可下載；刪除範本後連結列為 0                                   |
| 不保存案件欄位         | 沒有姓名、日期的資料表欄位；產生文件留在瀏覽器。內建類別不會寫入                                                                                                                                                                                                                                                                                                                                                                                                  | 範本表與類別表欄位檢查，稽核不含填寫內容                                       |
| 不內建案件類別         | 遷移只刪除固定種子編號。`SEED_SAMPLE_DATA` 或 `SEED_DEMO_USERS` 僅在非 production 放入示範範本，且不建立類別                                                                                                                                                                                                                                                                                                                                                      | 種子編號消失、自建編號保留；production 旗標不寫入示範範本                      |

登入階段是 httpOnly cookie。CSRF 權杖不是 httpOnly，讓同一個來源的頁面能放進標頭；其他網站讀不到這個 cookie。

## 依賴稽核

`pnpm audit` 在這次變更時沒有已知漏洞。之後若出現公告，先升級能相容的套件，再把仍無法排除的項目記在這裡。
